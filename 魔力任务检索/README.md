# 魔力宝贝怀旧服任务检索

纯静态离线工具，双击 `index.html` 即可使用，无需服务端。

## 首版功能

- 组合下拉框：既可下拉选择，也可直接输入任务名、俗称、系列名或拼音首字母。
- 聚焦输入框会临时清空当前任务名；若没有输入新内容，离开输入状态时会自动恢复原值。
- 模糊检索：支持包含、前缀和按顺序漏字匹配。
- 关系跳转：系列任务展示完整关系链、上一项和下一项；任务卡同时展示直接前置和后续索引。
- 任务正文：展示关键坐标、接取条件、逐步流程和注意事项，并保留原攻略链接供完整核验。
- 战斗资料：关键首领战记录等级、血量、数量、技能/特性和打法建议；无首领战会明确标注。
- 道具与奖励资料：上方流程始终保留取得道具的名称和步骤。纯流程道具不在下方重复；流程中取得但可装备、有属性或有独立使用价值的道具，仍在下方展示效果与属性。流程外奖励、BOSS 掉落和其他额外来源必须标明来源；装备数据与“魔力装备档案”交叉核验。
- 战斗掉落：与任务直接获得分栏展示。资料源明确写出的概率掉落、随机获得、必定获得会保留来源步骤或说明；装备同时展示档案属性，宠物蛋、图鉴、设计图等特殊掉落可在没有装备属性时单独保留。原文未提供概率数值时不推测百分比。
- 正文附注：来源页原“补充说明”会依据步骤号、道具、坐标、NPC 与地点挂回对应步骤；奖励/掉落说明归入收益区，战斗数据归入战斗区，只有无法归属单步的时段、组队、重做和失败条件保留为“全局注意事项”。
- 战斗资料：每个 BOSS 的技能/特性直接展示在该 BOSS 的数据卡片内（等级、血量、属性与技能同卡）；战斗级的技能串会按"首领名："前缀自动分配到对应敌人卡片，说明性长文字归入打法建议。
- 战斗拆分：`normalize.js` 归一化层会把爬取时被合并进同一 enemies 数组的多场战斗拆回独立战斗卡——识别"本体+小怪群"循环结构、同名本体重复出场、独立标签行（"训练设施 第N层…"）三类信号；迷宫场景资料之后的本体视为杂兵不拆；"召唤的分身：""喽啰："这类单一小怪标签并回同场；同名战斗卡用"敌人名·Lv"消歧。
- URL 定位：选择任务后写入 `#quest=任务ID`，刷新后仍可回到原任务。
- 本地离线：已核验专项详情在 `data.js`，魔力百科任务总表与逐页详情在 `catalog.js`；外链只用于打开原始攻略。
- 原图本地化：`source-documents.js` 记录图片与步骤、区域资料的对应关系，图片保存在 `assets/quests/`，离线打开仍可显示。
- 步骤标签：继续保留“道具要求、取得道具、使用道具、消耗道具、输入文字”；不再重复生成任务级“道具流转”表。
- 区域资料：原攻略中曾被旧爬取遗漏的普通怪资料会放回对应步骤，关键战斗仍在独立战斗区展示。
- 独立练级路线：任务若会开放或途经练级点，详情页显示“练级路线 / 完整任务流程”切换页签。练级页签从任务第1步逐项写到实际练级地图，并标出可以停止任务推进的位置，不再混进普通任务步骤。
- 旧任务补录：`enhancements.js` 维护目录抓取未覆盖的经典任务、搜索别名和练级路线关联，当前已补入改造僵尸、城内的地下迷宫、杀熊者欧兹那克、牛鬼讨伐、旅馆调查。
- 职业任务对账：`tools/build-career-quests.mjs` 会读取“魔力职业”的全部就职链接，按来源任务 ID 生成 `career-quests.js`；验证脚本要求每个职业的就职任务均已入库，避免逐条补录再次漏项。

## 结构化数据层

- `data-src/quests.json` 是统一的任务键值数据源，以稳定任务 ID 为键，集中保存元数据、来源原文、前置关系、主流程、版本、阶段、战斗、敌人、奖励、道具事件与逐行分类。
- `quest-data.js` 是为本地双击运行编译出的只读载入文件。页面会对 `verification.status` 为 `verified` 的任务直接按键读取结构化流程、版本、阶段、战斗与敌人；多版本奖励读取统一结构化奖励事件，既有专项奖励表继续保留专用排版。未完成核验的记录不会替换旧数据展示。
- 每条来源原文都保留行号，并且必须在 `segments` 中有且仅有一个分类结果；敌人、奖励和道具事件同时保留 `sourceLines`，便于回溯。
- `tools/build-structured-quests.mjs` 负责从现有权威入口全量重建 JSON 与离线载入文件；不要手工修改 `quest-data.js`。
- `tools/verify-structured-data.mjs` 检查任务数量、来源覆盖、版本键、唯一 ID、原文证据，以及“奖励宠物不得误判为敌人”等边界规则。

## 资料范围

采用“任务级保留、参数级裁剪”：未标服务器的旧任务视为通用任务并保留；明确含怀旧服版本的任务也保留。若同一任务同时存在道具服、时长服等多个版本，只采用怀旧服路线和参数；仅明确属于其他服务器且不含怀旧服版本的条目不进入工具。明确标注“怀旧服不可用”的任务（如苏之国市民权、艾尔巴尼亚市民权）整体不收录。

任务目录由 `tools/build-mission-catalog.mjs` 直接遍历魔力百科 `/Mission` 的全部分页，并逐条读取对应详情页，提取实际流程、坐标、条件、战斗数据、奖励与详情页中的任务链接。当前源站总表为 21 页、414 条；按本工具口径纳入 317 条，排除 95 条仅时长服/道具服任务与 2 条明确标注怀旧不可用的任务。连同本地专项补录后，页面当前可检索 319 个任务。完整纳入、排除与无步骤检查结果保存在 `mission-import-report.json`。

关闭中的怀旧历史活动仍会保留，并在数据中标记为 `availability: "closed"`；不会把它们显示成当前开放任务。所有任务均归入源页任务类型，页面严格依据详情页中的明确任务链接和《任务名》条件生成直接前置与直接后续，不用编号相邻冒充前置。

生成过程会删除详情中的道具服、时长服参数段，并对前置关系执行重复、断链、自引用和循环检查。若原攻略没有列出某个独立字段，页面不会用占位数据或推测内容冒充完整资料。

`reward-catalog.js` 是任务资料与 `魔力装备档案/index.html` 的交叉核验结果；重新整理奖励或掉落时，应同时检查任务步骤、补充说明和来源奖励栏，不能只读取任务最终一步。

任务数据不得在 `app.js` 渲染时临时拆字符串。来源页的任务类型与真正的系列字段分开保存；前后置只认 `prerequisites`。道具获取由 `normalize.js` 统一生成结构化 `acquisitions`：同一步多件道具合并为一个事件，输入道具和输出道具分开，并区分纯流程道具与有使用价值的成果。`KEY_ITEM_GUIDES` 根据后续任务要求与快速练级路线生成关键道具去向。构建或归一化规则有变化时，必须同步补充数据与 DOM 回归检查。

原攻略包含兑换表、概率表或多版本奖励时，使用 `structured-rewards.js` 将资料重组为获得事件、物品资料、兑换项目和版本差异。渲染层只能按这些字段排版，不能把整段原文临时塞进某个道具备注；同一道具的多个来源应合并到一份资料中。

兰国／艾国勋章系列按实际进度展示为“八等 → 七等 → 六等 → 五等 → 四等 → 三等 → 二等 → 一等”，前后置关系也按该方向生成。

更新全站目录时，在 `tools/` 目录执行 `npm run build:missions`，再执行 `npm run build`、`npm run verify:data`、`npm run verify` 与 `npm run verify:dom`。只重建统一任务数据时可执行 `npm run build:data`。目录之外的旧任务与任务练级路线放入 `enhancements.js`；人工核验的专项任务仍可在 `data.js` 中维护，并会优先于同名自动导入记录。
