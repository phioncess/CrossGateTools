## 结构化数据层

- `data-src/database.json` 与 `data-src/quests/*.json` 是统一的数据入口；每条任务按稳定任务 ID 单独保存，避免批次脚本反复覆盖整库。拆分前的单体快照与旧批次工具已移入 `_legacy-quarantine/2026-09-27/`，不参与构建、验证或事实回退。
- `quest-data.js` 是为本地双击运行编译出的只读载入文件。页面只读取 `verification.status` 为 `verified` 的结构化流程、版本、阶段、战斗、敌人、奖励与道具事件；未完成核验的数据会使发布失败，不再回退旧数据展示。
- `app.js` 直接消费 `QUEST_DATA.quests`；搜索索引只投影任务 ID、名称、别名、系列和类型，不复制任务事实。页面不再加载 `runtime-data.js`，也不在渲染阶段解析正文、补坐标、猜等待时间、恢复旧战斗或拼装旧奖励。
- 每条来源原文都保留行号，并且必须在 `segments` 中有且仅有一个分类结果；敌人、奖励和道具事件同时保留 `sourceLines`，便于回溯。
- `tools/quest-database.mjs` 是构建与数据验证共用的唯一装载器；缺少清单、任务文件名与 ID 不一致、重复 ID 或数量漂移都会失败。
- `tools/build-structured-quests.mjs` 只负责将分任务结构源单向发布为离线载入文件；结构源缺失或出现旧恢复字段时直接失败。不要手工修改 `quest-data.js`。
- `tools/verify-structured-data.mjs` 检查任务数量、来源覆盖、版本键、唯一 ID、原文证据，以及“奖励宠物不得误判为敌人”等边界规则。
- `tools/audit-data-contract.mjs` 生成 `data-contract-report.json`，持续盘点渲染器未消费的流程字段、逐行类型膨胀与待迁移任务；报告为 `migration-required` 时不得把现状描述为契约稳定。
- 页面不得因专用卡片暂未识别某个结构字段而静默丢弃数据。流程、战斗、轮次、区域遭遇与敌人记录中的扩展字段会进入“数据源补充”兜底展示；`verify:dom` 会遍历全部任务，确认流程扩展字段实际进入 DOM。`data-contract-report.json` 必须保持 `rendererUnhandledFieldCount: 0`，内部战斗引用与中间产物校验开关不得进入展示；题库使用昼夜表格。新增玩家事实字段须有明确展示去向，不得以内部字段可见作为验证通过条件。
- 对“存在战斗记录但没有敌人实体”的高风险任务，先运行 `npm run audit:sources`，逐页读取任务保存的原攻略 URL，并将网页正文与 `source.rawLines` 对账。原网页存在而本地未收录的段落必须先补入结构数据；只有来源覆盖为零遗漏且确实未提供敌人参数时，页面才不生成战斗资料卡。`verify:data` 会拒绝仍有未覆盖段落的来源审计报告。
- Schema v3 使用受控的逐行类别，并要求流程步骤只能包含渲染器明确消费的字段；未知字段、旧 `segments.type`、无效步骤引用或未核验证据会直接导致构建失败。v2 任务只作为迁移中数据保留，不得再扩展其自由字段。
