## 资料范围

采用“任务级保留、参数级裁剪”：未标服务器的旧任务视为通用任务并保留；明确含怀旧服版本的任务也保留。若同一任务同时存在道具服、时长服等多个版本，只采用怀旧服路线和参数；仅明确属于其他服务器且不含怀旧服版本的条目不进入工具。明确标注“怀旧服不可用”的任务（如苏之国市民权、艾尔巴尼亚市民权）整体不收录。

初始任务目录的历史导入器与导入报告已移入 `_legacy-quarantine/2026-09-27/`。当前正式范围为 319 条任务，隔离内容不属于发布链，也不能覆盖现行结构数据。

关闭中的怀旧历史活动仍会保留，并在数据中标记为 `availability: "closed"`；不会把它们显示成当前开放任务。所有任务均归入源页任务类型，页面严格依据详情页中的明确任务链接和《任务名》条件生成直接前置与直接后续，不用编号相邻冒充前置。

生成过程会删除详情中的道具服、时长服参数段，并对前置关系执行重复、断链、自引用和循环检查。若原攻略没有列出某个独立字段，页面不会用占位数据或推测内容冒充完整资料。

任务数据不得在 `app.js` 渲染时临时拆字符串。来源页分类与真正的系列字段分开保存；前后置只认结构化关系。道具输入、输出、奖励、兑换、概率、版本差异及装备档案交叉核验结果均写入 `QUEST_DATA`；同一步多件道具合并为一个事件，同一物品的多个来源合并展示。`KEY_ITEM_GUIDES` 只根据结构化道具事件、明确的后续任务关系和练级路线 `keyItems` 生成。

兰国／艾国勋章系列按实际进度展示为“八等 → 七等 → 六等 → 五等 → 四等 → 三等 → 二等 → 一等”，前后置关系也按该方向生成。

发布任务数据时，在 `tools/` 目录执行 `npm run audit:contract`、`npm run build:missions`，再执行 `npm run build`、`npm run verify:data`、`npm run verify` 与 `npm run verify:dom`。新增或修正任务必须修改 `data-src/quests/<任务ID>.json`；隔离目录只作历史备份，不得重新接入运行、构建或回退链。
